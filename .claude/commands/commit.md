# Git Commit

Review all staged and unstaged changes.

Then:

1. Group related changes into logical commits.
2. Write concise Conventional Commit messages.
3. Keep each commit focused on a single purpose.
4. Avoid mixing refactoring, features, and fixes in one commit.
5. Suggest if changes should be split into multiple commits.

Output:

- Recommended commit(s)
- Commit message(s)
- Short explanation for each commit
- Suggested commit order (if multiple)

Use Conventional Commits:

- feat:
- fix:
- refactor:
- perf:
- test:
- docs:
- chore:
- ci:
- build:
